# Telegram-бот: продажи Ozon

Бот получает отправления из Ozon Seller API и выдаёт количество заказанных единиц
по номенклатурам. Отменённые отправления не учитываются.

## Возможности

- отчёт по всем товарам за последние 30 дней по умолчанию;
- объединение заказов FBO и FBS;
- исключение отправлений со статусом `cancelled` и других статусов, содержащих `cancel`;
- выбор периода: 7, 14, 30, 60 или 90 дней;
- выбор всех или отдельных номенклатур через меню с пагинацией;
- постоянная кнопка `📋 Меню` под строкой ввода Telegram;
- сохранение настроек отдельно для каждого Telegram-пользователя в SQLite;
- доступ только для участников заданной Telegram-группы;
- обработка команд только внутри этой группы, без ответов в личных чатах;
- разбиение длинного отчёта на несколько сообщений.
- пятиминутный кэш списка номенклатур, чтобы переключение кнопок не создавало
  повторные запросы к Ozon.

В отчёте суммируется поле `quantity` товаров из неотменённых отправлений. Цены,
выручка и другие финансовые показатели не запрашиваются и не отображаются.

## Настройка

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`:

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `OZON_CLIENT_ID` — Client ID кабинета продавца Ozon;
- `OZON_API_KEY` — ключ Seller API;
- `ALLOWED_TELEGRAM_GROUP_ID` — числовой ID группы, участникам которой разрешён доступ.

Бот должен быть администратором этой группы: это необходимо для надёжной проверки
членства через `getChatMember`. Дополнительные административные разрешения ему не нужны.

Файл `.env` исключён из Git. Пользовательские настройки сохраняются в
`data/bot.sqlite3`, который также исключён из Git.

## Запуск через GitHub Actions

Основной режим работы — короткий запуск GitHub Actions раз в 5 минут. Каждый запуск
забирает накопившиеся обновления Telegram, обрабатывает их и завершается. Поэтому
ответ может прийти с задержкой примерно до 5 минут, а при задержке очереди GitHub —
позже.

В разделе репозитория `Settings → Secrets and variables → Actions` создайте пять
секретов:

- `TELEGRAM_BOT_TOKEN`;
- `OZON_CLIENT_ID`;
- `OZON_API_KEY`;
- `ALLOWED_TELEGRAM_GROUP_ID`;
- `STATE_ENCRYPTION_KEY` — случайный ключ шифрования служебной базы.

Workflow находится в `.github/workflows/telegram-bot.yml`. Его также можно запустить
вручную кнопкой `Run workflow` в разделе Actions.

Позиция очереди Telegram и пользовательские настройки хранятся в SQLite в отдельной
служебной ветке `bot-state`. База зашифрована AES-256; ключ хранится только в секрете
`STATE_ENCRYPTION_KEY`. Workflow обновляет эту ветку после каждого успешного запуска.
Одновременные запуски запрещены настройкой `concurrency`.

GitHub Actions не предоставляет входящий HTTPS endpoint, поэтому бот использует
`getUpdates`, а не webhook.

## Локальный запуск

```powershell
python -m ozon_sales_bot.bot
```

Это режим long polling для разработки и проверки на компьютере. Не запускайте его
одновременно с GitHub Actions: Telegram распределит обновления между двумя
получателями непредсказуемо.

Управление:

- кнопка `📋 Меню` — открыть меню настроек и отчёта;
- `/start` и `/menu` — резервный способ открыть меню;
- `/sales` — сразу получить отчёт с сохранёнными настройками.

## Ограничения Ozon API

Список выбора строится по номенклатурам, встречавшимся в неотменённых отправлениях за
последние 90 дней. Для товаров без заказов за этот период потребуется отдельно
подключить каталог товаров Seller API.
