# Веб-версия «Плана поставок» для iPhone

Интерфейс находится в `ozon_forecast/web/` и обслуживается тем же FastAPI:
`/` перенаправляет на `/web/`. Хостинг и отдельный аккаунт не нужны.
Доступ остаётся открытым по решению пользователя; себестоимость общая.
Действующие API и Android APK сохраняют свои маршруты.

## Работа с данными

- При открытии, поиске, настройке показателей и переключении разделов обращения к Ozon отсутствуют. Загружается последний отчёт из IndexedDB данного origin.
- Кнопка «Обновить» поставок вызывает `/api/v1/forecast?days=…&sales_days=…`. Данные и расчёт соответствуют параметрам **полученного** отчёта, включая резервный ответ сервера с другим историческим периодом.
- Кнопка «Обновить» рентабельности запускает `/api/v1/profitability/jobs` (сервер 0.7.7) и получает статус короткими запросами раз в три секунды. Показывается настоящий этап сервера. Повторный запуск для того же периода сервер объединяет. На 0.7.6 используется прежний GET с `refresh=true`; длительный запрос может ограничиваться прокси.
- Период по дням включает сегодня в часовом поясе отчёта (по умолчанию Europe/Moscow). От 1 до 365 дней, без будущих дат.
- Поставки: продажи FBO + FBS **в** кластер уже объединены сервером в строках FBO. Остатки и в пути FBS не отображаются. Количество к поставке: `max(0, ceil(продажи × прогноз / период продаж) − остаток − в пути)`. Запас: текущий остаток / средние продажи за день, округление до целого; при отсутствии продаж — «—».
- Прибыль товара: выручка − привязанные к заказу и SKU удержания − себестоимость × (выкуп − возврат). Расчёты сумм выполняются целыми копейками с BigInt. Нулевая себестоимость задана; отсутствующая не подменяется нулём.
- «Заработано за период» = прибыль всех товаров с себестоимостью − полные общие расходы Ozon. Поиск не меняет итог. Возвраты общих расходов уменьшают вычитаемую сумму. Если нет `expenses_complete=true` и согласованной детализации расходов, полный итог не показывается.
- Сохранение себестоимости вызывает только POST `/api/v1/profitability/cost`; после подтверждения сервера карточка, итог и локальный отчёт пересчитываются без запроса к Ozon. Время исходного финансового отчёта не меняется.

## iPhone и офлайн

В Safari: «Поделиться» (при необходимости через «Ещё») → «На экран Домой» → «Добавить». Если доступен переключатель «Открывать как веб-приложение», включить его. Встроенная инструкция открывается кнопкой ↗ в шапке. После установки открыть иконку и вручную обновить нужные отчёты.

Manifest задаёт `standalone`, scope и start_url `/web/`. Иконки 180/192/512 созданы из существующего `varanez_logo.png`. Поля имеют размер текста 16 px; учтены safe areas, узкие экраны и доступная высота диалога при клавиатуре.

Сервис-воркер работает по HTTPS (localhost разрешён для разработки), сохраняет **только белый список файлов интерфейса**, никогда не перехватывает API/POST или URL с параметрами. Финансовый отчёт хранится отдельно в IndexedDB, не в CacheStorage. Секреты Ozon браузеру не передаются. Обновление оболочки предлагается пользователю; текущая загрузка/редактирование не прерываются.

Сохранённый отчёт всегда содержит дату и период. При повторном открытии, ошибке сети, `stale=true` от сервера или возрасте более пяти минут показывается предупреждение о неподтверждённой свежести. Неудачный запрос или некорректный ответ не уничтожают предыдущий отчёт. Ошибка локального сохранения видна отдельно.

Ограничения: iOS может приостановить страницу в фоне и очистить данные сайта при нехватке места. Safari и установленное приложение могут иметь отдельное хранилище; офлайн-доступ требует предварительной загрузки в каждом из них. Фоновые задания выполняет сервер, без предположения о постоянной фоновой работе Safari. Нативная установка и клавиатура требуют проверки на настоящем iPhone.

Официальные источники, проверены 20.10.2026:

## Проверка и обновление сервера

Из актуального рабочего дерева:

```text
python -m pytest -q
node --test tests/web-model.test.mjs
node --check ozon_forecast/web/app.mjs
```

Тестовые финансовые данные синтетические. Реальные финансовые ответы не сохраняются в Git. Для запуска FastAPI используются прежние настройки сервера и его `.env`; веб-часть не требует новых ключей или npm-зависимостей.

Локальная проверка 20.10.2026: 101 Python-тест и 9 тестов JavaScript прошли. В браузере проверены ширины 320 и 390 px, раскрытие кластеров, поиск, фоновая загрузка со статусами, нулевая себестоимость и её сохранение. После полной остановки тестового сервера оболочка и оба отчёта успешно открылись из локального хранилища; ошибка ручного обновления сохранила предыдущие данные. В журнале тестового сервера навигация и поиск не вызывали API. Настоящий Safari/iPhone и публикация на Leo этой локальной проверкой не подтверждены.

На сервер необходимо передать **всю папку** `ozon_forecast/web/` и совместимый `ozon_forecast/api.py`, сохранив `.env`, `data/`, БД и `updates/ozon-plan.apk`. Для этапов фоновой загрузки нужен актуальный `profitability.py` 0.7.7. Обновлять согласованно с Android-веткой, затем перезапустить существующую задачу API. Наличие веб-файлов проверяется при старте: их отсутствие не блокирует запуск API.

После обновления проверить `/health`, `/api/v1/update`, `/web/`, manifest, JS и иконки. Открыть PWA, вручную загрузить отчёт, перезапустить без сети и проверить сохранённый отчёт. При изменении файлов оболочки повысить `VERSION` в `sw.js`, чтобы обновился атомарный кэш.

## Публикация на Leo — 20.10.2026

Адрес приложения: [План поставок](https://s63j9zcrvhd2.share.zrok.io/web/).

Передана только папка `ozon_forecast/web/` (10 файлов). Действующий `api.py` был предварительно получен в резервную копию и побайтно совпал с проверенным локальным исходником, поэтому Python-файлы на сервере не заменялись. После завершения и сохранения активного годового отчёта штатная задача `Ozon Forecast API` перезапущена через планировщик Windows.

Проверено по HTTPS: все 10 файлов совпадают с локальными исходниками, MIME для JavaScript и CSS корректны, `/health` сообщает 0.7.7. Метаданные и SHA-256 Android APK совпали до и после. Сохранённый 90-дневный отчёт, время его загрузки и контрольная сумма общей себестоимости не изменились; отчёты за 90 и 365 дней прошли клиентскую проверку формата и полноты общих расходов. Веб-интерфейс успешно загрузил настоящий план поставок. Попытка свежего финансового обновления через веб получила штатный ответ 409: на общем сервере уже загружается другой отчёт; новая финансовая загрузка этой проверкой не подтверждена. Себестоимость при проверке не записывалась. На настоящем iPhone установка ещё не проверена.
